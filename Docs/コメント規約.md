# コメント規約

本ドキュメントは、このプロジェクトにおけるコメントの書き方の基準をまとめたものです。
`CLAUDE.md`にある「コメントは"なぜ"を書く。コードから分かる説明は禁止。」という方針を、
具体的な書式のレベルまで落とし込んだものです。既存コードのコメントを見直す際は、
このドキュメントの基準を判断基準にしてください。

---

## 基本方針
- コメントは最小限にする。
- 意図の説明は、本当に分かりにくい箇所にだけ最低限書く。無くても読めるなら書かない。
- `//`コメントは1行で書く。複数行にまたがる説明文は書かない。
- コメントに`()`は使わない。
- `============`や`------------`のような区切り線コメントは、.h/.cppどちらでも使わない。

---

## .hファイル
コメントは `///<summary>...</summary>` 形式で書く。1行にまとめず、`<summary>`と`</summary>`は
必ず改行する。

```cpp
///<summary>
///初期化。アトラスの読み込みも内部で行う
///</summary>
bool Initialize(...);
```

---

## .cppファイル
コメントはメソッドの中にだけ書く。メソッドの外(ファイル冒頭、名前空間直下、関数と関数の間)には書かない。
メソッド内でも、本当に分かりにくい箇所にだけ、1行で最低限のコメントを書く。

Good:
```cpp
void Foo()
{
    // ラスタライザ
    ...
}
```

Bad(メソッド外へのコメント、区切り線):
```cpp
// ============================
//  初期化処理
// ============================
bool TextRenderer::Initialize(...)
{
    ...
}
```

---

## 禁止する書き方
- `============` / `------------` 等の区切り線コメント。.h/.cppどちらも対象。
- 複数行にわたる`//`コメント。
- コメント内での`()`の使用。
- .cppファイルでメソッドの外に書くコメント。
- 日付入りの経緯コメントを長々と書くこと。理由は会話やコミットメッセージ側に残せば十分。

---

## 元のコメントが文字化けしている場合
文字化けして元の文言が読み取れないコメントを見つけた場合、無理に復元しようとしない。
クラス名・メソッド名・周辺コードから意図を判断し、この規約に沿った適切なコメントを新しく書く。

---

## 判断に迷ったときの基準
- そのコメントを消しても、コードを読むだけで同じ情報が得られるなら書かない。
- 本当に分かりにくい箇所・過去にハマった箇所・性能上あえて不自然な書き方をしている箇所だけ、
  1行で最低限書く。
